GLIP topic-page data contract
=============================

The updated front end calls the Apps Script action:

    getTopicPageData

Purpose
-------
Return the authoritative context and ordered activity menu for one topic page.
The server must enforce the same role, active and visibility rules used by the
Topics page. The browser must not be trusted to decide access.

Accepted request fields
-----------------------
school_id
curriculum_id
 topic_id
 topic_code
 subject_id
 subject_code
 level_id
 level
 userType
 teacher_id
 student_id

The server should resolve by stable IDs first. Codes are fallbacks for direct
links and migration compatibility.

Recommended successful response
-------------------------------
{
  "status": "success",
  "topic_page": {
    "school": "raphael",
    "curriculum_id": "12",
    "level": {
      "level_id": "4",
      "level_code": "level-04",
      "level_name": "Level 4"
    },
    "subject": {
      "subject_id": "word",
      "subject_code": "word",
      "subject_name": "MS Word"
    },
    "topic": {
      "topic_id": "word_l4_t2",
      "topic_code": "topic-02",
      "topic_name": "Text to Table"
    },
    "activities": [
      {
        "activity_id": "word_l4_t2_lesson1",
        "activity_title": "Lesson 1",
        "activity_type_code": "lesson",
        "sort_order": 10,
        "visible": true,
        "active": true,
        "file_name": "lesson-01.html"
      }
    ]
  }
}

Implementation notes
--------------------
1. Resolve curriculum, subject and topic relationships on the server.
2. Return only activities that the current role is allowed to know about.
3. Sort by numeric sort_order, then by activity_id for deterministic output.
4. Prefer an explicit file_name. During migration, the front end can derive a
   conventional file name from activity_type_code and the activity ID suffix.
5. Validate that file_name is a plain file name, not an external URL or path.
6. Do not use the owner-only listActivitiesOwner action for learner pages.
7. Reuse the relational snapshot/cache rather than reading each sheet separately.

Activities must include activity_code. GLIP uses activity_code + ".html" as the local published filename. activity_id remains the relational key and progress-column identifier.
