Help Centre Integration *

Purpose

GLIP uses one shared Help Centre for the entire platform. All help content is stored in:

/help/help.html

Individual GLIP pages do not require separate help files. Instead, each page identifies the section of the Help Centre that should open when the user selects Help.

This approach provides one source of truth, reduces maintenance and allows related pages to share the same instructions.

How the Help button works

Every GLIP page defines a logical Help section key in its page configuration. 

window.PAGE_CONFIG = {
  pageTitle: "Teacher Management",
  pageKind: "management",
  helpSection: "teacher-management"
};

The shared header reads the value of helpSection. It then opens the Help Centre and passes the requested section in the URL. 

/help/help.html?section=teacher-management

The Help Centre finds the matching section, expands it and scrolls to it automatically.

Logical Help keys

A Help key identifies a feature. It is not required to match the HTML filename or folder name.

Use lowercase words separated by hyphens, for example:

teacher-management
student-management
topic-management
subjects-home
topics-home
activity
progress-management
content-validator
performance-monitor

Avoid spaces, underscores and capital letters.

Teacher Management
teacher_management
TeacherManagement

Why Help keys are independent of filenames

The Help Centre should continue to work when a page is renamed or moved.

For example, a page named: 

teacher-management.html

could later be renamed to:

staff-management.html

The Help integration would remain unchanged as long as the page keeps: 

helpSection: "teacher-management"

The logical key represents the feature rather than its current file location.

Adding Help to a new page

When a new GLIP page is created, complete the following steps.

  1. Add a logical helpSection value to the page's PAGE_CONFIG.
  2. Add a matching collapsible section to /help/help.html.
  3. Set the roles that should see the section using data-roles.
  4. Test the Help button while logged in using each relevant role.

Example page configuration:

window.PAGE_CONFIG = {
  pageTitle: "New Management Page",
  pageKind: "management",
  helpSection: "new-management-page"
};

Matching Help Centre section:

<details
  class="help-topic"
  id="new-management-page"
  data-roles="admin owner">

  <summary>New Management Page</summary>

  <div class="help-topic-body">
    <section class="help-subsection">
      <h3>Overview</h3>
      <p>Add the instructions here.</p>
    </section>
  </div>

</details>

The section's id must exactly match the page's helpSection value.

Adding a general Help section

A Help section does not need to be linked to a GLIP page. General guidance can be added directly to the Help Centre.

For example:

<details
  class="help-topic"
  id="about-glip"
  data-roles="student subject_teacher lead_teacher admin owner">

  <summary>About GLIP</summary>

  <div class="help-topic-body">
    <section class="help-subsection">
      <h3>What is GLIP?</h3>
      <p>Add the general information here.</p>
    </section>
  </div>

</details>

The section will appear in the Help Centre and in Help search results, even though no page opens it automatically.

Sharing one Help section between several pages

Several pages can use the same Help section by assigning them the same logical Help key.

For example, lessons, practices, quizzes, reflections and other learning activities can all use: 

helpSection: "activity"

They will all open the following shared section: 

<details class="help-topic" id="activity">
  ...
</details>

This should be used when the instructions are common to the pages, such as uploading work, using drag and drop, enlarging images and recording progress.

Duplicate page names

Duplicate filenames do not require special handling because Help is controlled by logical keys rather than filenames.

Pages with the same filename may share one Help section: 

helpSection: "settings"

The shared section may contain separate subsections for the different contexts in which the page is used.

Alternatively, pages with the same filename may use different Help keys when their instructions are substantially different. 

helpSection: "admin-settings"

helpSection: "student-settings"

The choice should be based on whether sharing the instructions makes the Help Centre clearer and easier to maintain.

Role visibility

Use the data-roles attribute to specify which roles can see a Help section.

Owner only:

data-roles="owner"

Administrators and owners:

data-roles="admin owner"

Teaching roles, administrators and owners:

data-roles="subject_teacher lead_teacher admin owner"

All normal GLIP roles:

data-roles="student subject_teacher lead_teacher admin owner"

A section without data-roles is treated as general Help and may be displayed to all users.

Role filtering is used to keep the Help Centre relevant and uncluttered. It is not a security mechanism.

Role-specific information inside a shared section

A Help section can be visible to several roles while containing subsections that apply only to particular roles. 

<div data-roles="subject_teacher">
  <h3>Subject teachers</h3>
  <p>Instructions for subject teachers.</p>
</div>

<div data-roles="lead_teacher">
  <h3>Lead teachers</h3>
  <p>Instructions for lead teachers.</p>
</div>

<div data-roles="admin owner">
  <h3>Administrators and owners</h3>
  <p>Administrative instructions.</p>
</div>

Use this approach when the overall feature is shared but each role has different responsibilities or permissions.

Help section structure

Each major Help entry should use the existing help-topic, help-topic-body and help-subsection classes. 

<details class="help-topic" id="feature-key" data-roles="owner">
  <summary>Section title</summary>

  <div class="help-topic-body">

    <section class="help-subsection">
      <h3>First subsection</h3>
      <p>Instructions...</p>
    </section>

    <section class="help-subsection">
      <h3>Second subsection</h3>
      <p>More instructions...</p>
    </section>

  </div>
</details>

Use one top-level details element for each major Help topic. Use one or more help-subsection blocks to organise the detailed instructions.

Search behaviour

The Help Centre search looks through the section title, subsection headings and instruction text.

Search results are limited to Help content available to the current role. Matching sections are opened automatically and sections that do not match are temporarily hidden.

Use meaningful headings and clear wording so users can find guidance using ordinary search terms.

Page information comment

Each functional HTML page should contain a developer comment identifying its logical Help section. 

<!--
=========================================================
GLIP PAGE INFORMATION

Help Centre:
    /help/help.html

Help Section:
    teacher-management

=========================================================
-->

Keep the comment synchronised with the page's PAGE_CONFIG.helpSection value.

Testing a new Help section

  1. Open the relevant GLIP page.
  2. Select Help.
  3. Confirm that the Help Centre opens in a new tab.
  4. Confirm that the correct section expands automatically.
  5. Confirm that the Help Centre scrolls to the section.
  6. Test the Help search using words from the new section.
  7. Test each role listed in data-roles.
  8. Confirm that roles not listed in data-roles do not see the section.
  9. Check the Help page at normal, large and larger text sizes.
  10. Check the section using the available GLIP themes and display settings.

Maintenance principles

  • Keep all user guidance in the single /help/help.html file.
  • Do not create separate Help files for individual pages.
  • Reuse existing Help sections where the guidance is genuinely shared.
  • Create a new logical key only when a feature needs distinct instructions.
  • Keep Help keys independent of filenames and folder locations.
  • Use role filtering to show users only the guidance relevant to them.
  • Reuse GLIP's existing CSS classes and visual language.
  • Avoid adding page-specific Help JavaScript when the shared framework can handle the behaviour.
  • Keep instructions clear enough for teachers and students who are not technically experienced.

Naming Subject and Topic Icons *

Why must the file names follow a specific format?

GLIP automatically locates subject and topic icons using the subject code and topic code stored in Google Sheets. No filenames are hardcoded in the system.

To ensure that the correct icon is displayed, the image filename must match the corresponding code exactly.

If GLIP cannot find the expected image, the generic icon will be shown instead.

Naming a subject icon

Each subject icon is stored directly under content/subjects.

Required file name:

{subject_code}.jpg

Replace {subject_code} with the exact value stored in the subject_code column of the Subjects sheet.

Example:

If the subject code is:

subject_a

the icon must be named:

subject_a.jpg

and saved in:

content/subjects/subject_a.jpg

Naming a topic icon

Each topic icon is stored directly in the topic's folder under content/topics.

Required file name:

{topic_code}.jpg

Replace {topic_code} with the exact value stored in the topic_code column of the Topics sheet.

Example:

If the topic code is:

topic_a

the icon must be named:

topic_a.jpg

and saved in:

content/topics/topic_a/topic_a.jpg

Important naming rules

  • Use the subject code and topic code exactly as they appear in Google Sheets.
  • Use the same name for the folder and its icon.
  • New subject icons should use the exact subject code. GLIP also accepts the older icon-{subject_code}.jpg name as a compatibility fallback.
  • Do not add suffixes such as _icon.
  • Do not replace underscores with spaces or hyphens.
  • File names are case-sensitive. Lower-case filenames are recommended.

Example folder structure

Following this convention makes the content structure easy to understand. Every folder simply contains an image with the same name as the folder itself.

Creating Lesson Pages *

Purpose

A lesson page should contain only information that Google Sheets cannot provide. GLIP reads the subject name, topic name, activity title, curriculum and level from the relational records in Google Sheets.

This avoids duplicated metadata and prevents hardcoded values from becoming inconsistent with Activity Management or Curriculum Management.

New lesson workflow

  1. Create the activity in Activity Management.
  2. Copy the current lesson template into the correct topic folder.
  3. Rename the HTML file using the activity file name.
  4. Enter the activity ID in LESSON_CONFIG.
  5. Update the required-file and video settings.
  6. Update the lesson introduction, learning outcomes and instructions.
  7. Test the headings, download, video, progress buttons and navigation.

The lesson configuration block

window.LESSON_CONFIG = {
  activityId: "1",

  fileLink: "DIRECT_OR_SHAREABLE_FILE_LINK",
  fileButtonText: "Download Word file",

  posterImage: "text_to_table_lesson_video_image.jpg",
  videoUrl: "EMBEDDABLE_VIDEO_PREVIEW_URL"
};

Do not add subjectId, topicId, level, subjectName, topicName or activityTitle. GLIP obtains them from Google Sheets.

Activity identity

activityId

This is the immutable Activity ID stored in the Activities sheet. It is the only relational identifier entered in the lesson page.

GLIP uses it to locate the activity record and obtain the activity title. The activity is linked through the topic and curriculum records, allowing GLIP to obtain the correct subject and level automatically.

Metadata read from Google Sheets

GLIP supplies the following automatically:

  • subject ID and subject name;
  • topic ID and topic name;
  • activity title;
  • curriculum ID;
  • level ID and level code;
  • the correct progress context for the learner.

The browser title, lesson hero, video labels and progress-saving configuration are generated from this authoritative metadata.

Required file settings

fileLink

Enter the direct or shareable link to the file required for the lesson. Check that learners have permission to open or download it.

fileButtonText

Enter the wording shown on the button, such as Download Word file.

Leave fileLink blank when the lesson does not require a downloadable file.

Video settings

posterImage

Enter the relative path to the preview image in the topic's assets folder. Use lower-case snake_case filenames.

videoUrl

Enter the embeddable video URL. For Google Drive, use the URL ending in /preview.

Educational content

Edit only the clearly labelled lesson-content sections, including:

  • the lesson introduction;
  • the learning outcomes;
  • required-file instructions;
  • video instructions.

Do not edit

  • the generated PAGE_CONFIG block;
  • shared JavaScript references;
  • shared CSS classes;
  • progress button IDs;
  • accessibility attributes;
  • the shared page structure.

Testing checklist

  1. Confirm that the subject, topic and activity titles match Google Sheets.
  2. Confirm that the correct level and curriculum are being used.
  3. Open the required file.
  4. Play the video.
  5. Test both progress buttons as a student.
  6. Confirm that topic and subject progress badges update correctly.
  7. Test keyboard access to the video poster.
Activity Management *

Purpose

Activity Management is used to create and maintain the learning activities that make up each topic in GLIP. Activities define the order in which learners complete work and are used for navigation, progress tracking and content validation.

Every activity belongs to a single topic and has a unique Activity ID and Activity Code. The Activity ID is used internally by GLIP, while the Activity Code identifies the corresponding HTML content page.

Adding an activity

To add an activity:

  1. Select the required Level, Subject and Topic.
  2. Select the Activity Type.
  3. Enter a descriptive Activity Title.
  4. Specify the Sort Order.
  5. Choose whether the activity is Visible and Active.
  6. Save the activity.

GLIP generates the Activity ID automatically and suggests an Activity Code based on the title.

Activity ID and Activity Code

The Activity ID is the internal database identifier used by GLIP to maintain relationships between activities and learner progress. It is generated automatically and should never be edited manually.

The Activity Code is a permanent content identifier. It is used to locate the HTML page that contains the learning material.

For example: 

Activity Code: my_lesson_01

HTML page:
my_lesson_01.html

Once an activity has been created, the Activity Code should not be changed because it forms part of the content structure and may be referenced by links, validation routines and other resources.

Sort Order

The Sort Order determines the sequence in which activities appear to learners.

It is recommended to number activities in multiples of ten, for example: 

10
20
30
40

This makes it easy to insert additional activities later without having to renumber the entire topic.

Visible and Active

Two settings control whether an activity is available.

  • Visible determines whether learners can see the activity.
  • Active determines whether the activity is available for use.

An activity must normally be both Visible and Active before learners can access it.

Owners can still view inactive activities for planning and development purposes.

Editing activities

Existing activities can be edited using the Edit Activities button.

Changes are applied immediately in the browser and then saved in the background. Modified fields are highlighted until the changes have been saved successfully.

The Activity Code is treated as a permanent identifier and should not normally be changed after the activity has been created.

Searching and sorting

The Activities table supports searching, sorting and filtering to make it easier to locate activities in large courses.

You can search across all columns or limit the search to a specific field.

Relationship with Content Validator

Every activity should have a matching HTML content page whose filename matches the Activity Code.

The Content Validator checks for:

  • activities without matching HTML pages;
  • HTML pages that are not linked to any activity;
  • duplicate Activity Codes;
  • other content consistency issues.

Running the Content Validator regularly helps ensure that the published content remains complete and consistent.

Learning Activities

Using an activity page

Activity pages may contain written instructions, videos, images, links, questions and interactive tasks. Follow the instructions shown on the page and complete each part in order.

Uploading work:
Where an upload option is provided, select the requested file from your device and wait for the upload to finish before leaving the page.

Drag and drop:
Drag each item to the appropriate answer area. On a touch screen, press and hold the item briefly before moving it.

Magnifying images:
Select an image when the magnify option is available. The enlarged image can then be closed to return to the activity.

Progress:
Use the completion control provided on the page when you have finished the activity. Do not close the page while a save or upload is still in progress.

Level Management

Level Management
This page is used to manage the levels offered by the school.

Purpose
Levels define the structure of the school in GLIP. Classes, subject assignments, teaching assignments and student subject assignments all depend on levels.

Examples
level-03 – Level 3
level-04 – Level 4
level-05 – Level 5

Level Code
The unique code used internally by GLIP. It should remain stable because other records refer to it.

Level Name
The display name shown in GLIP.

Sort Order
Controls the order in which levels appear throughout GLIP. It must be a whole number of 1 or greater.

Status
Active levels can be used for new classes and subject setup. Inactive levels can be used for planning. Records linked to inactive levels may show ⚠ on other management pages, and students and teachers will not see those items until the level is active.

Class Management

Add Class

Use this form to add a new class to GLIP. Every class must belong to an existing level.

Level
Select the level to which the class belongs.

Only levels that already exist in Level Management are shown. This field is required. If the required level is not shown, add it in Level Management first.

Class Code
The Class Code is the unique identifier used internally by GLIP. Every class must have a different Class Code.

GLIP does not require one fixed naming format. You may use any format that suits the school's existing practice, provided that each code is unique.

Class Codes are stored in lower case. If capital letters are entered, GLIP converts them to lower case automatically. For example, Year7-A-26 is stored as year7-a-26.

Examples:
4.1
4.1-26
year7-a
y7blue
foundation-1
evening-b
science-group-2

Recommended year suffix
Although it is not required by GLIP, it is strongly recommended to include the scholastic year at the end of the Class Code, for example:

4.1-26
4.1-27
year7-a-26

GLIP treats the whole Class Code as one identifier. It does not read the final digits as a year and it does not automatically know that 4.1-26 is followed by 4.1-27.

The year suffix is recommended because it helps administrators to:
* distinguish classes from different scholastic years
* retain historical class records without reusing the same code
* prepare future classes before the current year ends
* identify revision classes from previous years
* avoid confusion when the same class name is used every year

For example, 4.1-26 and 4.1-27 are treated as two completely different classes.

This field is required and must be unique.

Class Label
The Class Label is the name shown to users throughout GLIP.

GLIP does not require one fixed label format. Use a clear name that teachers, administrators and students will understand.

Examples:
4.1
Year 7 Blue
Foundation Group 1
Evening Class
Physics Revision
4A (Girls)
STEM A

The Class Label does not need to be unique, but it should clearly identify the group.

Sort Order
Enter a whole number to control the order in which classes appear in tables and dropdown lists. Smaller numbers appear before larger numbers.

Recommended practice: use values such as 10, 20, 30, 40 rather than 1, 2, 3, 4.

Using tens leaves space to insert another class later without renumbering the existing classes. For example, a new class can be inserted between 20 and 30 by giving it Sort Order 25.

Do not leave Sort Order blank. Do not use text, negative numbers or 0.

Status
Choose whether the class is active or inactive.

Active classes are available for normal use. Inactive classes remain stored for planning or historical reference but should not normally be used for new assignments.

Save Class
Select Save Class to add the class. GLIP creates the internal class ID automatically. You do not need to enter class_id or level_id.

Class Management

Use this area to view and manage the classes stored in GLIP. Classes are linked to levels and are used when assigning students, teachers and subjects.

Viewing Classes
The table shows all classes currently stored in GLIP. Each class belongs to one level and has a unique Class Code and a user-friendly Class Label.

Class Code
The Class Code is the unique identifier used by GLIP.

Class Codes are stored in lower case. If capital letters are entered manually or through a CSV import, GLIP converts them to lower case automatically.

GLIP does not interpret the code or determine class progression from it. For example, GLIP does not automatically know that 4.1-26 is followed by 4.1-27.

A year suffix is strongly recommended because it makes historical, current, future and revision classes easier to distinguish.

Examples:
4.1-26
4.1-27
year7-a-26
foundation-1-26

Class Codes should remain stable once they are in use because they are used during CSV imports and when linking other records to classes.

Class Label
The Class Label is the name displayed to users.

Examples:
4.1
Year 7 Blue
Foundation Group 1
Physics Revision
Evening Class

The label may be changed without changing the internal class identity.

Sort Order
Sort Order controls the order in which classes appear in tables, dropdown lists and other management pages.

Recommended practice: use values such as 10, 20, 30, 40. This leaves room to insert a new class later, for example 25 between 20 and 30, without renumbering existing records.

Status
Active classes are available for normal use.

Inactive classes are retained for planning or historical reference but should not normally appear in selection lists for new assignments.

Sorting
Select any column heading to sort the table. Select the same heading again to reverse the order.

Edit Classes
Select Edit Classes to switch the table into edit mode. Modified fields are highlighted so that pending changes are easy to see.

Select Save Changes to save all edited records. Select Cancel to discard unsaved changes.

Import CSV
Use the exported CSV as the import template.

Existing classes are matched using the Class Code. If the code already exists, the existing class is updated. If the code does not exist, a new class is created.

GLIP validates the complete file before importing it.

Validation checks may include:
* missing or invalid level
* missing Class Code
* duplicate Class Code
* missing Class Label
* invalid status
* invalid Sort Order

Error Report
If validation errors are found, GLIP can provide a CSV report showing the problems that must be corrected.

Automatic Backup
Before importing or clearing the table, GLIP downloads a backup copy of the current class data.

Clear Table
Clear Table removes all class records while keeping the column headings. Use this only when you are certain that the class list should be rebuilt.
Subject Catalogue *

Subject Catalogue

Purpose
The Subject Catalogue defines which subjects are available for use by this school.

Only subjects that are marked Active can be assigned to levels through Subject Management.

This page does not assign subjects to levels. That is done separately in Subject Management.

Subject
Shows the name of each subject available in the catalogue.

Code
The internal subject code used by GLIP. Examples:
physics
word
excel
chemistry

Subject codes are normally created once and should remain unchanged.

Used by curriculum
This column shows how many curriculum records currently use the subject.

For example:
Not used
1 assignment
3 assignments

If a subject is already used by the curriculum and is later made inactive, the curriculum records are preserved but the subject will no longer be available to teachers or students.

Status
Active
The subject is available for use throughout GLIP and may be assigned to levels in Subject Management.

Inactive
The subject remains stored in GLIP but cannot be used for new curriculum assignments. Existing curriculum records are preserved for historical and planning purposes.

Where do these subjects come from?
The list is read from the Subjects sheet in the school's Google spreadsheet.

If subjects are added to the Subjects sheet, they will automatically appear in this catalogue the next time the data is refreshed.

The Subject Catalogue therefore reflects the contents of the Subjects sheet while allowing the owner to control which subjects are currently available for use.
Topic Catalogue *

Topic Catalogue

Purpose
The Topic Catalogue defines which topics are available for use by the school.

Topics are organised by subject. Select a subject from the dropdown list to view the topics associated with it.

This page does not assign topics to particular levels. Topic assignments are managed separately in Topic Management.

Subject dropdown
Only subjects marked as Active in the Subject Catalogue appear in the subject dropdown.

If a subject is missing, check its status in Subject Catalogue first.

Making a subject inactive does not delete its topics. However, the subject and its topics will no longer be available for normal curriculum setup until the subject is made active again.

Topic name
The Topic Name is the friendly title shown to owners, administrators, teachers and students.

Examples:
Forces and Motion
Electricity
Working with Tables

The topic name may be displayed throughout GLIP wherever the topic is used.

Topic code
The Topic Code is the internal code used by GLIP to identify the topic.

The code must correspond exactly to the topic folder used on GitHub.

For example, if the Topic Code is:

topic-01

the matching topic folder on GitHub should also be:

topic-01

The spelling, numbering and use of hyphens must match. A mismatch may prevent GLIP from finding the topic home page, images or other content stored inside the folder.

Topic codes should normally use lower-case letters and hyphens, for example:

topic-01
topic-02
forces-and-motion

Used by curriculum
This column shows how many curriculum topic assignments currently use the topic.

Examples:
Not used
Assigned to 1 subject


A topic may be used by more than one level or curriculum subject assignment.

If a topic is marked inactive while it is assigned to a subject, the topic will no longer be available to students and teachers until it is made active again.

Status
Active
The topic is available for curriculum use and may be assigned through Topic Management.

Inactive
The topic remains stored in GLIP but cannot be used for new topic assignments. Existing assignments are preserved for historical records, planning and possible future reactivation.

Important: changes affect the whole school
The Topic Catalogue is a school-wide catalogue.

Changing a Topic Name changes the name wherever that topic is displayed across the school.

Changing a Topic Code is more serious because the code is used to connect GLIP records with the topic folder and content stored on GitHub.

A code change may affect:
* topic assignments
* topic links
* topic home pages
* images and other files
* activities linked to the topic
* existing content paths

Before changing a Topic Code, confirm that the matching GitHub folder and all related references will also be updated.

Do not change a topic name or code for one class or one level only. The same catalogue topic may be used throughout the school, so the change affects every level, class, teacher and student using it.

Editing topics
Select Edit Topics to change topic availability or any other fields permitted by the page.

Modified fields are highlighted before saving.

Select Save Changes to apply the updates. Select Cancel to discard unsaved changes.
Subject Management

Add Subject Assignment


Use this page to assign subjects to levels.

Subject assignments determine which subjects are available for each level in GLIP.

For example, if Word and Excel are assigned to Level 4, students and teachers in Level 4 will only see those subjects (subject to their own permissions).

Subject Management does not create new levels or new subjects. Levels must already exist in Level Management and subjects must already exist in Subject Management before they can be linked together.

Level
Select the level to which the subject should belong.

Examples:
level-03
level-04
level-05

Only existing levels can be selected.

Subject
Select the subject that will be available for the selected level.

Examples:
Word
Excel
PowerPoint

Only existing subjects can be selected.

Visibility
Visibility determines whether the subject is shown to users.

TRUE = Students, teachers and administrators can see the subject (provided they have permission).
FALSE = The subject remains assigned to the level but is hidden from users.

Visibility is useful when preparing a subject before it is released or when temporarily hiding a subject without removing its assignment to the level.

Changing Visibility does not delete any student progress or teacher assignments.

Status
Status determines whether the subject assignment itself is active.

TRUE = The subject assignment is active.
FALSE = The subject assignment is inactive.

If the subject assignment is active but the selected level is inactive, GLIP shows the status as Active (pending). This means the record has been prepared, but it will not be available to students or teachers until the level is activated.

Inactive subject assignments are normally used to preserve historical information from previous academic years while preventing new assignments.

If a subject assignment is no longer required but historical data should be retained, it is usually better to set Status to FALSE rather than delete the record.

Sort Order
Sort Order controls the order in which subjects appear throughout GLIP.

Examples:
1
2
3

Subjects with lower numbers appear first.

Recommended practice: use values such as 10, 20, 30, 40 instead of consecutive numbers. This makes it easy to insert additional items later without renumbering the existing ones.

Student Management

Student Management
This page is used to create, edit, import, export and manage student accounts in GLIP.

Selecting Students
Click a row to select a student. Hold Ctrl while clicking to select or deselect multiple students. Hold Shift and click another row to select all students between the two rows.

Send Selected Codes
Select one or more students and click Send Selected Codes to email their GLIP login details. The system reports how many emails were sent successfully and how many failed. Students without a valid email address are skipped and reported as failed.

Edit Students
Click Edit Students to switch the table into edit mode. Student details can then be updated directly within the table. After editing student records, click Save Changes to update the database. Modified fields are highlighted before saving. Cancels edit mode and discards any unsaved changes made during the current editing session.

Levels and Classes
Each student must belong to a level and a class. Changing the level automatically updates the available class list. Only classes belonging to the selected level can be chosen.

Account Status
Active students can log in and access GLIP normally. Inactive students remain in the database but cannot log in until reactivated.

Export CSV
Exports all student records to an administrator-friendly CSV file. The exported file uses clear codes such as level_code and class_code rather than internal database IDs. The file may be edited in Excel and imported again later.

Import CSV
Imports student records from a CSV file by using the exported CSV as the template. Existing students are matched using their login code and are updated automatically while new (unique) student codes create new student records. Internal IDs are generated and managed automatically by GLIP.

CSV Import Format
Use the exported CSV as the template.

CSV Validation
Before any import is performed, GLIP validates the file structure, required fields, level and class combinations, email formats, duplicate student codes and other data integrity rules. Imports containing errors are blocked until the issues are corrected.

Import Backups
Before importing a CSV file, GLIP automatically downloads a backup of the current student table. This allows records to be restored if required.

Clear Table
Removes all student records from the Students table while keeping the column headings. A backup CSV is automatically downloaded before the table is cleared.

Student Codes
Student login codes should be unique. During CSV imports, the login code is used to determine whether a student should be updated or added as a new record.

Email Addresses
Email addresses are optional. Multiple students may share the same email address if required. However, students without an email address will not be able to receive login details by email.
