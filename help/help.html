Help Centre Integration

Purpose

GLIP uses one shared Help Centre for the entire platform. All help content is stored in:

/help/help.html

Individual GLIP pages do not require separate help files. Instead, each page identifies the section of the Help Centre that should open when the user selects Help.

This approach provides one source of truth, reduces maintenance and allows related pages to share the same instructions.

How the Help button works

Every GLIP page defines a logical Help section key in its page configuration. 

window.PAGE_CONFIG = {
  pageTitle: "Teacher Management",
  pageKind: "management",
  helpSection: "teacher-management"
};

The shared header reads the value of helpSection. It then opens the Help Centre and passes the requested section in the URL. 

/help/help.html?section=teacher-management

The Help Centre finds the matching section, expands it and scrolls to it automatically.

Logical Help keys

A Help key identifies a feature. It is not required to match the HTML filename or folder name.

Use lowercase words separated by hyphens, for example:

teacher-management
student-management
topic-management
subjects-home
topics-home
activity
progress-management
content-validator
performance-monitor

Avoid spaces, underscores and capital letters.

Teacher Management
teacher_management
TeacherManagement

Why Help keys are independent of filenames

The Help Centre should continue to work when a page is renamed or moved.

For example, a page named: 

teacher-management.html

could later be renamed to:

staff-management.html

The Help integration would remain unchanged as long as the page keeps: 

helpSection: "teacher-management"

The logical key represents the feature rather than its current file location.

Adding Help to a new page

When a new GLIP page is created, complete the following steps.

  1. Add a logical helpSection value to the page's PAGE_CONFIG.
  2. Add a matching collapsible section to /help/help.html.
  3. Set the roles that should see the section using data-roles.
  4. Test the Help button while logged in using each relevant role.

Example page configuration:

window.PAGE_CONFIG = {
  pageTitle: "New Management Page",
  pageKind: "management",
  helpSection: "new-management-page"
};

Matching Help Centre section:

<details
  class="help-topic"
  id="new-management-page"
  data-roles="admin owner">

  <summary>New Management Page</summary>

  <div class="help-topic-body">
    <section class="help-subsection">
      <h3>Overview</h3>
      <p>Add the instructions here.</p>
    </section>
  </div>

</details>

The section's id must exactly match the page's helpSection value.

Adding a general Help section

A Help section does not need to be linked to a GLIP page. General guidance can be added directly to the Help Centre.

For example:

<details
  class="help-topic"
  id="about-glip"
  data-roles="student subject_teacher lead_teacher admin owner">

  <summary>About GLIP</summary>

  <div class="help-topic-body">
    <section class="help-subsection">
      <h3>What is GLIP?</h3>
      <p>Add the general information here.</p>
    </section>
  </div>

</details>

The section will appear in the Help Centre and in Help search results, even though no page opens it automatically.

Sharing one Help section between several pages

Several pages can use the same Help section by assigning them the same logical Help key.

For example, lessons, practices, quizzes, reflections and other learning activities can all use: 

helpSection: "activity"

They will all open the following shared section: 

<details class="help-topic" id="activity">
  ...
</details>

This should be used when the instructions are common to the pages, such as uploading work, using drag and drop, enlarging images and recording progress.

Duplicate page names

Duplicate filenames do not require special handling because Help is controlled by logical keys rather than filenames.

Pages with the same filename may share one Help section: 

helpSection: "settings"

The shared section may contain separate subsections for the different contexts in which the page is used.

Alternatively, pages with the same filename may use different Help keys when their instructions are substantially different. 

helpSection: "admin-settings"

helpSection: "student-settings"

The choice should be based on whether sharing the instructions makes the Help Centre clearer and easier to maintain.

Role visibility

Use the data-roles attribute to specify which roles can see a Help section.

Owner only:

data-roles="owner"

Administrators and owners:

data-roles="admin owner"

Teaching roles, administrators and owners:

data-roles="subject_teacher lead_teacher admin owner"

All normal GLIP roles:

data-roles="student subject_teacher lead_teacher admin owner"

A section without data-roles is treated as general Help and may be displayed to all users.

Role filtering is used to keep the Help Centre relevant and uncluttered. It is not a security mechanism.

Role-specific information inside a shared section

A Help section can be visible to several roles while containing subsections that apply only to particular roles. 

<div data-roles="subject_teacher">
  <h3>Subject teachers</h3>
  <p>Instructions for subject teachers.</p>
</div>

<div data-roles="lead_teacher">
  <h3>Lead teachers</h3>
  <p>Instructions for lead teachers.</p>
</div>

<div data-roles="admin owner">
  <h3>Administrators and owners</h3>
  <p>Administrative instructions.</p>
</div>

Use this approach when the overall feature is shared but each role has different responsibilities or permissions.

Help section structure

Each major Help entry should use the existing help-topic, help-topic-body and help-subsection classes. 

<details class="help-topic" id="feature-key" data-roles="owner">
  <summary>Section title</summary>

  <div class="help-topic-body">

    <section class="help-subsection">
      <h3>First subsection</h3>
      <p>Instructions...</p>
    </section>

    <section class="help-subsection">
      <h3>Second subsection</h3>
      <p>More instructions...</p>
    </section>

  </div>
</details>

Use one top-level details element for each major Help topic. Use one or more help-subsection blocks to organise the detailed instructions.

Search behaviour

The Help Centre search looks through the section title, subsection headings and instruction text.

Search results are limited to Help content available to the current role. Matching sections are opened automatically and sections that do not match are temporarily hidden.

Use meaningful headings and clear wording so users can find guidance using ordinary search terms.

Page information comment

Each functional HTML page should contain a developer comment identifying its logical Help section. 

<!--
=========================================================
GLIP PAGE INFORMATION

Help Centre:
    /help/help.html

Help Section:
    teacher-management

=========================================================
-->

Keep the comment synchronised with the page's PAGE_CONFIG.helpSection value.

Testing a new Help section

  1. Open the relevant GLIP page.
  2. Select Help.
  3. Confirm that the Help Centre opens in a new tab.
  4. Confirm that the correct section expands automatically.
  5. Confirm that the Help Centre scrolls to the section.
  6. Test the Help search using words from the new section.
  7. Test each role listed in data-roles.
  8. Confirm that roles not listed in data-roles do not see the section.
  9. Check the Help page at normal, large and larger text sizes.
  10. Check the section using the available GLIP themes and display settings.

Maintenance principles

  • Keep all user guidance in the single /help/help.html file.
  • Do not create separate Help files for individual pages.
  • Reuse existing Help sections where the guidance is genuinely shared.
  • Create a new logical key only when a feature needs distinct instructions.
  • Keep Help keys independent of filenames and folder locations.
  • Use role filtering to show users only the guidance relevant to them.
  • Reuse GLIP's existing CSS classes and visual language.
  • Avoid adding page-specific Help JavaScript when the shared framework can handle the behaviour.
  • Keep instructions clear enough for teachers and students who are not technically experienced.

Learning Activities

Using an activity page

Activity pages may contain written instructions, videos, images, links, questions and interactive tasks. Follow the instructions shown on the page and complete each part in order.

Uploading work:
Where an upload option is provided, select the requested file from your device and wait for the upload to finish before leaving the page.

Drag and drop:
Drag each item to the appropriate answer area. On a touch screen, press and hold the item briefly before moving it.

Magnifying images:
Select an image when the magnify option is available. The enlarged image can then be closed to return to the activity.

Progress:
Use the completion control provided on the page when you have finished the activity. Do not close the page while a save or upload is still in progress.

Examples:
1

Status

Level Management

Level Management
This page is used to manage the levels offered by the school.

Purpose
Levels define the structure of the school in GLIP. Classes, subject assignments, teaching assignments and student subject assignments all depend on levels.

Examples
level-03 – Level 3
level-04 – Level 4
level-05 – Level 5

Level Code
The unique code used internally by GLIP. It should remain stable because other records refer to it.

Level Name
The display name shown in GLIP.

Sort Order
Controls the order in which levels appear throughout GLIP. It must be a whole number of 1 or greater.

Status
Active levels can be used for new classes and subject setup. Inactive levels can be used for planning. Records linked to inactive levels may show ⚠ on other management pages, and students and teachers will not see those items until the level is active.

No Deletion
Levels are not deleted through GLIP. If a level is no longer used, mark it as inactive. This protects historical data and avoids breaking links to existing classes, subject assignments, students and progress records.

CSV Export and Import
The CSV uses administrator-friendly columns:

level_code,level_name,sort_order,active

Example:
level-03,Level 3,1,TRUE
level-04,Level 4,2,TRUE
level-05,Level 5,3,TRUE
Class Management

Add Class

Use this form to add a new class to GLIP. A class must belong to an existing level.

Level
Select the level to which the class belongs.

Only levels that already exist in the Levels table are shown in this list. This field is required. If the required level is not shown, it must first be added to the Levels table.

Class Code
Enter a short, unique code for the class. This code identifies the class internally and is also used during CSV import to update existing classes. Use a stable format such as 4A-26, where 4A is the class and 26 refers to the academic year ending in 2026.

Accepted examples:
3A-25
4A-26
5A-26
4B-26

This field is required and must be unique.

Examples that will generate an error:
blank value
a class code that already exists when adding a new class
4A 26

Class Label
Enter the class name as users should see it in GLIP.

Accepted examples:
3A (main)
4A (main)
4A (Boys)
4A (Girls)
5A (main)

This field is required.

Examples that will generate an error:
blank value

The class label does not need to be unique, but it should be clear for users.

Sort Order
Enter a number to control the order in which classes appear in tables and dropdown lists.

Accepted examples:
1
2
3
10

Examples that will generate an error:
abc
first
1A
4A-26

Use whole numbers only. Smaller numbers appear before larger numbers.

Status
Choose whether the class is active or inactive.

Accepted values:
Active
Inactive

Active classes are available for normal use. Inactive classes remain stored for reference but should not normally appear in selection lists.

Save Class
Click Save Class to add the class to the Classes table. GLIP will create the internal class ID automatically. You do not need to type class_id or level_id.

Class Management

Use this area to manage the classes available in GLIP. Classes are linked to levels and are used throughout the system when assigning students, teachers and subjects.

Viewing Classes
The table displays all classes currently stored in GLIP. Each class belongs to a level and has a unique class code and a user-friendly class label.

Level
Shows the level to which the class belongs.

Examples:
Level 3
Level 4
Level 5

Class Code
The unique code used internally by GLIP to identify a class.

Examples:
3A-25
4A-26
5A-26

The first part identifies the class itself. For example, 4A refers to class 4A.

The last two digits identify the academic year. For example:
4A-25 = academic year 2024–2025
4A-26 = academic year 2025–2026
4A-27 = academic year 2026–2027

This allows GLIP to distinguish between classes from different academic years and retain historical records for revision and reporting purposes.

Class codes should remain stable because they are used during CSV imports and when linking students, teachers and subjects to classes.

Class Label
The name displayed to users throughout GLIP.

Examples:
3A (main)
4A (main)
4A (Boys)
4A (Girls)

The label can be changed without affecting existing student or teacher assignments.

Sort Order
Controls the order in which classes appear in tables, dropdown lists and other management pages.

Classes with smaller numbers appear before classes with larger numbers.

Status
Shows whether the class is active or inactive.

Active classes are available for normal use.
Inactive classes are retained for reference but should not normally appear in selection lists.

Sorting
Click any column heading to sort the table. Click the same heading again to reverse the sort order.

Edit Classes
Click Edit Classes to switch the table into edit mode. Editable fields will appear directly inside the table. Any fields you modify are highlighted so that you can easily see pending changes before saving. Click Save Changes to save all edited class records at once. Click Cancel to discard all unsaved changes and reload the current data from GLIP.

Import CSV
Imports classes from a CSV file.

Before any data is changed, GLIP validates the entire file and displays a validation summary.

Examples of validation checks include:
Missing level
Invalid level
Missing class code
Duplicate class code
Missing class label
Invalid status value
Invalid sort order

Existing classes are matched using the class code. If the class code already exists, the existing class is updated.
If the class code does not exist, a new class is created automatically.

Error Report
If validation errors are found, you can download a CSV report showing all problems that must be corrected before importing again.

Automatic Backup
Before any import or table clear operation, GLIP automatically downloads a backup copy of the current data.

Clear Table
Removes all class records from the Classes table while keeping the column headings intact.
Subject Management

Add Subject Assignment


Use this page to assign subjects to levels.

Subject assignments determine which subjects are available for each level in GLIP.

For example, if Word and Excel are assigned to Level 4, students and teachers in Level 4 will only see those subjects (subject to their own permissions).

Subject Management does not create new levels or new subjects. Levels must already exist in Level Management and subjects must already exist in Subject Management before they can be linked together.

Level
Select the level to which the subject should belong.

Examples:
level-03
level-04
level-05

Only existing levels can be selected.

Subject
Select the subject that will be available for the selected level.

Examples:
Word
Excel
PowerPoint

Only existing subjects can be selected.

Visibility
Visibility determines whether the subject is shown to users.

TRUE = Students, teachers and administrators can see the subject (provided they have permission).
FALSE = The subject remains assigned to the level but is hidden from users.

Visibility is useful when preparing a subject before it is released or when temporarily hiding a subject without removing its assignment to the level.

Changing Visibility does not delete any student progress or teacher assignments.

Status
Status determines whether the subject assignment itself is active.

TRUE = The subject assignment is active.
FALSE = The subject assignment is inactive.

If the subject assignment is active but the selected level is inactive, GLIP shows the status as Active (pending). This means the record has been prepared, but it will not be available to students or teachers until the level is activated.

Inactive subject assignments are normally used to preserve historical information from previous academic years while preventing new assignments.

If a subject assignment is no longer required but historical data should be retained, it is usually better to set Status to FALSE rather than delete the record.

Sort Order
Sort Order controls the order in which subjects appear throughout GLIP.

Examples:
1
2
3

Subjects with lower numbers appear first.

Example:
1 Word
2 Excel
3 PowerPoint

Sort Order should normally contain whole numbers.

Save Subject Assignment
Creates the subject assignment and immediately makes it available according to the Visibility and Status settings.

What causes an error?
An error will be shown if:

* the level is not selected
* the subject is not selected
* the same level and subject combination already exists
* Visibility is not TRUE or FALSE
* Status is not TRUE or FALSE
* Sort Order is missing or is not a valid number

Subject Management


Use this page to view, edit, export, import and manage the subjects assigned to each level in GLIP.

Subject assignments control which subjects belong to each level.

Every subject shown to students, teachers and administrators must be assigned to the appropriate level here.

For example:

Level 3 → PowerPoint
Level 4 → Word, Excel
Level 5 → Word

Only subjects assigned to a level here can later be assigned to teachers and students.

If a subject has not been assigned to a particular level, it cannot be assigned to students or teachers, even if the subject itself exists.

⚠ and amber strip
⚠ indicates that the level is inactive in the Level Management page. The amber strip on the left marks an active record linked to an inactive parent. The row remains editable for planning purposes, but it is not available to teachers or students until the level is activated.

Visibility
Visibility controls whether a subject is displayed to users.

TRUE = The subject is visible.
FALSE = The subject is hidden.

Active subjects linked to an inactive level are shown as pending. This is useful when preparing new material before students begin studying it or when temporarily hiding a subject during the academic year.

Hidden subjects remain in the database and can be made visible again at any time.

Status
Status shows whether the subject assignment is active and whether it is ready for use.

Active = The subject assignment is active and its level is active.
Active (pending) = The subject assignment is active, but its level is inactive. This is used when preparing future subject assignments. It is not available to students or teachers yet.
Inactive = The subject assignment itself is inactive.

Inactive subject assignments are normally retained for historical reference and previous academic years. Inactive is generally preferable to deleting subject assignments because it preserves historical information.

Sort Order
Sort Order determines the order in which subjects appear throughout GLIP.

Example:

1 Word
2 Excel
3 PowerPoint

Changing the Sort Order changes only the display order. It does not affect student progress, teacher assignments or permissions.

What is allowed?
You may:

* add new subject-level combinations
* edit Visibility
* edit Status
* change Sort Order

Each subject can appear only once for a particular level.

The same subject may be assigned to multiple levels.

Examples:

✓ Level 3 → Word
✓ Level 4 → Word
✓ Level 5 → Word

✗ Level 4 → Word (entered twice)

What causes an error?
An error will be shown if:

* the level does not exist
* the subject does not exist
* the same level and subject combination already exists
* Visibility is not TRUE or FALSE
* Status is not TRUE or FALSE
* Sort Order is missing or is not a number
* the imported CSV contains missing or incorrect column headings

CSV Import Format
Always use the exported CSV as the template.

Example:

level_code,subject_code,visible,sort_order,active
level-03,powerpoint,TRUE,1,TRUE
level-04,word,TRUE,1,TRUE
level-04,excel,TRUE,2,TRUE
level-05,word,TRUE,1,TRUE

Important notes
Before importing or clearing the table, GLIP automatically downloads a backup of the current subject assignments.

If validation errors are found, the import will be blocked until the problems have been corrected.

Changes made to subject assignments may affect which subjects are available to students and teachers throughout GLIP.

Curriculum Topic Management

Curriculum Topic Management

Use this page to manage which topics belong to each subject at each level.

Topics are linked to curriculum items (Level + Subject). For example:

Level 3 → Physics → Topic 1
Level 3 → Physics → Topic 2
Level 3 → Physics → Topic 3
Level 4 → Physics → Topic 1
Level 4 → Chemistry → Topic 1

⚠ and amber strip
The ⚠ symbol indicates that this topic assignment depends on an inactive parent record (for example an inactive level, curriculum item or topic). They remain editable so that future work can be prepared before it is released to teachers and students.

Visible
Visibility controls whether a topic is shown to users. Changing Visibility never deletes student progress or teacher assignments. Visible = The topic is displayed to users who have permission to access that subject. Hidden = The topic remains stored but is not displayed.

If the assignment is active but one of its parent records is inactive, the topic is shown as Visible (pending). This means the topic is ready but will not become visible until the parent record is activated.

Status
Status controls whether the topic assignment itself is active. Active = The topic assignment is available for use. Active (pending) = The assignment is active but one or more parent records are inactive. The assignment has been prepared but is not yet available. Inactive = The topic assignment itself has been deactivated. Inactive records are normally retained for historical reference rather than deleted.

Sort Order
Sort Order determines the order in which topics appear within a subject. The numbering restarts for each subject. Changing the Sort Order changes only the display order. It does not affect student progress or teacher assignments.

Edit Topic Assignments
Click Edit Topic Assignments to modify existing records.

You may:

* change Visibility
* change Status
* change Sort Order

The linked level, subject and topic cannot be changed after the record has been created. If a different combination is required, create a new assignment instead.

Adding Topic Assignments
When creating a new topic assignment:

If the required level and subject do not appear in the first list, they must first be added in Curriculum Management.

If the required topic does not appear in the second list, check that:

* the topic has already been created in Topic Management;
* the topic belongs to the selected subject;
* the topic is active.

Each topic may appear only once for the same Level and Subject combination.

What causes an error?
An error will be shown if:

* the level and subject are not selected;
* the topic is not selected;
* the same topic is already assigned to the selected Level and Subject;
* Sort Order is missing or is not a whole number;
* Visibility is not TRUE or FALSE;
* Status is not TRUE or FALSE.

Sort Order determines the order in which topics appear within a subject. The numbering restarts for each subject. Changing the Sort Order changes only the display order. It does not affect student progress or teacher assignments.

Edit Topic Assignments
Click Edit Topic Assignments to modify existing records.

You may:

* change Visibility
* change Status
* change Sort Order

The linked level, subject and topic cannot be changed after the record has been created. If a different combination is required, create a new assignment instead.

Adding Topic Assignments
When creating a new topic assignment:

If the required level and subject do not appear in the first list, they must first be added in Subject Management.

If the required topic does not appear in the second list, check that:

* the topic has already been created in Topic Management;
* the topic belongs to the selected subject;
* the topic is active.

Each topic may appear only once for the same Level and Subject combination.

What causes an error?
An error will be shown if:

* the level and subject are not selected;
* the topic is not selected;
* the same topic is already assigned to the selected Level and Subject;
* Sort Order is missing or is not a whole number;
* Visibility is not TRUE or FALSE;
* Status is not TRUE or FALSE.

Student Management

Student Management
This page is used to create, edit, import, export and manage student accounts in GLIP.

Selecting Students
Click a row to select a student. Hold Ctrl while clicking to select or deselect multiple students. Hold Shift and click another row to select all students between the two rows.

Send Selected Codes
Select one or more students and click Send Selected Codes to email their GLIP login details. The system reports how many emails were sent successfully and how many failed. Students without a valid email address are skipped and reported as failed.

Edit Students
Click Edit Students to switch the table into edit mode. Student details can then be updated directly within the table. After editing student records, click Save Changes to update the database. Modified fields are highlighted before saving. Cancels edit mode and discards any unsaved changes made during the current editing session.

Levels and Classes
Each student must belong to a level and a class. Changing the level automatically updates the available class list. Only classes belonging to the selected level can be chosen.

Account Status
Active students can log in and access GLIP normally. Inactive students remain in the database but cannot log in until reactivated.

Export CSV
Exports all student records to an administrator-friendly CSV file. The exported file uses clear codes such as level_code and class_code rather than internal database IDs. The file may be edited in Excel and imported again later.

Import CSV
Imports student records from a CSV file by using the exported CSV as the template. Existing students are matched using their login code and are updated automatically while new (unique) student codes create new student records. Internal IDs are generated and managed automatically by GLIP.

CSV Import Format
Use the exported CSV as the template.

CSV Validation
Before any import is performed, GLIP validates the file structure, required fields, level and class combinations, email formats, duplicate student codes and other data integrity rules. Imports containing errors are blocked until the issues are corrected.

Import Backups
Before importing a CSV file, GLIP automatically downloads a backup of the current student table. This allows records to be restored if required.

Clear Table
Removes all student records from the Students table while keeping the column headings. A backup CSV is automatically downloaded before the table is cleared.

Student Codes
Student login codes should be unique. During CSV imports, the login code is used to determine whether a student should be updated or added as a new record.

Email Addresses
Email addresses are optional. Multiple students may share the same email address if required. However, students without an email address will not be able to receive login details by email.
Teaching Assignments

Add Teaching Assignment


Use this page to assign teachers to classes and subjects.

A teaching assignment tells GLIP which teacher is responsible for a particular subject within a particular class.

Example:
Peter Borg → Physics → 4A-26

This assignment allows the teacher to access the subject, view students and record progress for the assigned class.

Before creating assignments
Teaching assignments depend on records that already exist elsewhere in GLIP.

Before creating an assignment, make sure that:

* the teacher exists in Teacher Management
* the class exists in Class Management
* the level exists in Level Management
* the subject exists in Subject Management
* the subject has been assigned to the level through Subject Management

If any of these records do not exist, they must be created first.

For example:
If you want to assign a teacher to class 4A-27 but that class has not yet been created in Class Management, the assignment cannot be created until the class exists.

Similarly, if a new level or subject is required, it must first be created in the appropriate management page before assignments can be made.

Active
The Active field determines whether the assignment is currently available in GLIP.

TRUE = The assignment is active and available to the teacher.
FALSE = The assignment is archived and hidden from normal use.

Assignments are normally set to TRUE.

You may set an assignment to FALSE if:
* a teacher is no longer teaching the class
* the assignment belongs to a previous academic year
* the assignment needs to be retained for historical reference but should no longer be used

GLIP does not delete teaching assignments through this page. Set Active to FALSE to retain the assignment for historical reference and allow it to be reactivated later.

What causes an error?
An error will be shown if:

* a required field is left blank
* the teacher does not exist
* the class does not exist
* the subject does not exist
* the level or subject assignment is missing
* the active value is not TRUE or FALSE
* the CSV contains missing or incorrect column headings

CSV Import Format
Use the exported CSV file as the template for imports.

Example:

teacher_code,class_code,subject_code,access_type,can_view_progress,can_override,active
PB001,4A-26,physics,current,TRUE,TRUE,TRUE
PB001,4A-26,chemistry,current,TRUE,TRUE,TRUE
MB002,5A-26,geography,current,TRUE,FALSE,TRUE

Important notes
Before importing or clearing the table, GLIP downloads a backup of the current data.

If validation errors are found, the import will be blocked and a summary of the problems will be displayed.

Teaching assignments are not deleted through GLIP. To remove current access while retaining the record, set Active to FALSE.

Teaching Assignments


Use this page to add, edit, export, import or clear classes used in GLIP.

Classes are linked to students, subject assignments and teaching assignments. For this reason, class records should be kept stable once they are in use.

Class Code
The class code is the short code used by GLIP to identify the class.

Examples:
3A-25
4A-26
5A-26

The first part normally identifies the level and class group. The last two digits normally identify the academic year. For example, 4A-26 can be used for class 4A in the academic year ending in 2026.

Class Label
The class label is the name shown to users.

Examples:
3A (main)
4A (main)
5A (Evening)

Level
Each class must be linked to one valid level.

Examples:
level-03
level-04
level-05

Active
Use TRUE for classes currently in use.
Use FALSE to archive classes that should no longer be used for new assignments.

Sort Order
Sort order controls the order in which classes appear in lists.

What is allowed?
You can add new classes, edit existing class labels, change the level, change the active status and change the sort order.

Class codes should be unique. Do not use the same class code for two different classes.

What causes an error?
An error will be shown if:

* a required field is left blank
* the class code is already used by another class
* the level does not exist
* the active value is not TRUE or FALSE
* the sort order is missing or is not a number
* the imported CSV has missing or incorrect column headings

CSV Import Format
When importing, use the same headings as the exported CSV file. Do not rename, remove or reorder the headings unless the import instructions say this is allowed.

Example CSV:

class_code,class_label,level_code,active,sort_order
3A-25,3A (main),level-03,TRUE,1
4A-26,4A (main),level-04,TRUE,2
5A-26,5A (main),level-05,TRUE,3
4B-26,4B (Evening),level-04,TRUE,4

Important notes
Before importing or clearing the table, GLIP downloads a backup of the current data.

If the CSV contains errors, the import will be blocked. Correct the CSV and import it again.

Clearing the table removes all class records apart from the headings. Only do this if you are sure that you want to rebuild the class list.
